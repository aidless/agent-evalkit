# 模拟面试 Q&A — agent-evalkit（30 分钟高压版）

15 个追问，全部答案锚定仓库里的真实数字。回答原则：先给结论，再给数字，最后主动交代边界。

## 开场题

**Q1. 用 60 秒讲清楚 agent-evalkit 是什么、解决什么问题。**

「工具调用型 agent 上线前需要回答三个问题：能不能完成任务、失败时为什么、改动有没有让它退化。我用纯标准库写了一个确定性评测 harness：24+12 道任务、逐事件 JSONL trace、五类失败归因、阈值 0.80 的 fail-closed 门禁。两个后端实测：网关模型 ×5 平均 0.9666±0.0272，本地 Qwen3-4B-AWQ ×4 稳定 0.9722——两个后端分数分开、失败画像不同，证明评测集有区分度。CI 里门禁挡住了一个真回归（max-turns=1 时 0/24，exit 1）。」

## 设计判断类（必追问）

**Q2. 为什么评分不用 LLM 当裁判？**

「确定性评分保证两次跑同一结果可以逐题对账。裁判模型自己有方差——我用网关 ×5 实测过非确定性抖动：三次 0.9444、两次 1.0000，每次红灯的题还不一样。如果把裁判再叠上去，方差会乘起来。代价是只能评有唯一答案的任务，所以我加对抗题把集子扩到 36 题。」

**Q3. 失败归因为什么定这个优先级：api_error/orchestration_error > loop_exceeded > no_answer > tool_missing > wrong_answer？**

「越早失败的错误掩盖后面的信号：API 挂了什么都测不到；先判 loop_exceeded 再看有没有答案，否则空转会同时记 no_answer 造成双罚。这个顺序让我在 adv-05 案例里能把「模型在工具报错后思考螺旋 2048 tokens 未闭合」从一堆 wrong_answer 里剥出来归为截断。」

**Q4. fail-closed 的门禁怎么保证自己不是装饰？**

「selftest 里 8 条检查有 3 条是反证：喂 0.5 的报告必须 BLOCK、喂五类缺字段的坏报告必须非零退出。真流量上也验过一次：max-turns=1 跑 24 题 0 通过，门禁 exit 1。CI 每次推送都重跑这个反证。」

**Q5. trace 为什么逐事件 flush？**

「评测跑到一半被 kill 是常态——flush 每 13KB 磁盘写换的是「崩了也留尸检证据」。实测一次：本地 6GB 卡上跑全量时 Ollama 抢显存把服务打崩，trace 里最后的事件精确停在崩的位置。」

## 数字深挖类

**Q6. 0.9666±0.0272 和 0.9722±0.0000 这两个数怎么读？**

「网关侧 sd=0.0272 来自 ×5 里三次 0.9444 两次 1.0000——**非确定性抖动**，红灯题每次不同（lookup-01/08、multi-01 轮流挂）。本地侧 ×4 完全一致 35/36，唯一失败 adv-05 三次复现失败链相同——**确定性失败**。所以一个是方差问题一个是能力问题，归因完全不同。」

**Q7. ¥0.0051 怎么算的，口径是什么？**

「51.9W（GPU 窗口实测均值）×592s = 0.008533 kWh ×¥0.6/kWh。口径只算 GPU 电：不含整机、折旧、机房。跟卡片里 ¥0.043/1M output 是两个口径——那个是吞吐折算，这个是一次全量评测总电费。面试官问口径差别时要主动分清。」

**Q8. prefix-cache 命中率 0.9178 是什么？**

「run 前后抓 Prometheus 计数器差值。0.9178 = 评测 run 共享系统提示词前缀被 KV cache 复用的比例。中间有个插曲：短 prompt 冒烟读到 0，我先是错怪计数器没接线，后又错怪 LBNHC layout 提了上游 issue——最后用源码级调试定位：**不足一个 16-token block 的 prompt 从不参与哈希，永不命中，这是 block 粒度缓存的设计行为**。issue 已自撤（vllm#66786 关闭 not_planned）。教训：报 bug 前先做单变量对照实验，长度就是那个变量。」

**Q9. 本地后端 p99 延迟 33 秒，这个服务能用吗？**

「不能用——这是 6GB 显存 + Ollama 共存时 gpu-mem-util 0.585 的配置，KV cache 只剩 2,224 tokens、并发上限 1.09x。这正是要它当**对照**的原因：同一套集子、同一套评分，唯一变量是后端。真正的部署读数在另一张卡（vllm-serving-card）：c=1 TTFT p99 212ms、c=4 吞吐 243 tok/s（CUDA graph），交互式并发上限推导为 4。」

## 对抗案例类

**Q10. adv-05 失败的完整链路？**

「嵌套括号表达式 (1+((2+(3*(4+(5*(6+1)))))))。本地模型 turn1 发畸形表达式 → AST 白名单拒 SyntaxError 包成 ToolError 回灌 → 模型陷入「禁心算」指令和修正欲望的冲突 → 思考写满 2048 tokens 未闭合 → finish_reason=length 被截断守卫拦下判 orchestration_error。三臂修复实验全失败：放宽 max_tokens 到 4096 连工具都不调了、改提示词也不行——结论是 4B 模型对这条指令的能力边界，不是 harness 缺陷，负结果写进了 README。」

**Q11. 两个真 harness bug 怎么被发现的？**

「都是本地后端跑出来的，网关满分会把它们藏住：① 模型发不平衡括号 "(1+2" → ast.parse 抛 SyntaxError 逃出 dispatch 的异常白名单 → 误判 orchestration_error；② finish_reason=length 时 content 为空 → 旧代码把空串当最终答案。修法：SyntaxError 进异常白名单、截断且无内容直接判失败并发 error 事件。两个都先写了 RED 测试。」

**Q12. replay/mock-LLM 有什么用？**

「把 trace 里的 llm_call 事件按 (task_id, 调用序) 回放，agent 循环完全不碰网络。用途：① 确定性验收——gw7 新跑 36/36 满分，回放逐题一致 0 mismatch；② 评分逻辑的回归测试不烧 token；③ 崩溃现场复盘。」

## 工程边界类

**Q13. 评测集天花板在哪？**

「24 题版本对网关 24/24 满分，零区分度——这是我在数字卡片里主动承认的最大短板，所以才有 v2 的 12 道对抗题。36 题版本两个后端都不到 1.0 且失败模式分开。下一步该扩到 100+ 题并加多步链，但按「先证明可复现再扩张」的纪律，先把小集子的证据链跑通。」

**Q14. 和 LangSmith/RAGAS 这类产品的差异？**

「它们是托管观测平台，我在做的是**可复现的验收标准**：门禁要进 CI、失败要归因到类、数字要能从落盘证据重算。不冲突——trace 事件设计成 JSONL 就是想哪天接进它们的 viewer。另外零依赖是硬约束：评测工具本身不该把安装面搞大。」

**Q15. 这个项目最硬和最不硬的数字？**

「最硬：两个 harness 真 bug 有 RED 测试锁住；门禁挡住真回归 exit 1；issue 自撤有完整根因链。最不硬：36 题样本量小，0.9666±0.0272 的 sd 估计非常粗糙（×5），别拿它当统计结论——这是测「区分度存在性」不是测「精确通过率」。」
